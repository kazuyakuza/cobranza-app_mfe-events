# TODO 01 — Project Scaffold & Package Bootstrap

**Source of truth:** `docs/mfe-events-project-brief.md` (and this TODO)  
**Repo type:** Standalone git repository (this repo *is* the library; not a monorepo)  
**Goal of this TODO only:** Turn the repository into a clean, buildable TypeScript library package with correct identity, layout, and empty public API. **No event constants, payloads, helpers, or real documentation content yet.**

## Constraints for this TODO

- **No Angular.** This package must not depend on `@angular/*`.
- **No RxJS, no event-bus class, no Angular services.**
- **No domain event implementation yet** (no `MFE_EVENTS`, no payloads, no helpers beyond a placeholder export if needed to keep the build green).
- Prefer a **simple** build: `tsc` alone is acceptable; `tsup` or similar is fine if already natural for the repo. Avoid heavy tooling.
- Single public entry is enough for v1 (`src/public-api.ts` or `src/index.ts` re-exporting the public surface).

## Tasks

### 1. Establish package identity

- [ ] Ensure `package.json` name is exactly:

  ```json
  "@cobranza-apps/mfe-events"
  ```

- [ ] Set version to `0.1.0` (or keep existing if already set and intentional).
- [ ] Set a clear `description`, for example:
  > Typed event contracts and helpers for communication between the Cobranza Company Back-office Shell and its micro-frontends.
- [ ] Set `license`, `author` / `repository` only if already present in sibling packages or the base project; do not invent private org details.
- [ ] Ensure `"type": "module"` **or** a dual CJS/ESM setup consistent with the chosen build. Prefer ESM-first if starting clean.
- [ ] Set `"sideEffects": false`.

### 2. TypeScript configuration

- [ ] Add / align `tsconfig.json` for a **library** (not an application):
  - Target suitable for modern browsers + Angular 22 consumers (e.g. `ES2022` or `ES2020`).
  - `"declaration": true`, `"declarationMap": true` recommended.
  - `"strict": true` (or as strict as sibling `@cobranza-apps/*` packages).
  - Module resolution compatible with bundlers / Node16 / bundler mode.
  - `rootDir` / `outDir` pointing at `src` → `dist` (or the convention already used in the repo).
- [ ] Ensure the config does **not** pull in Angular compiler options.
- [ ] `tsc --noEmit` (or the project’s typecheck script) must succeed on the empty/minimal sources.

### 3. Source layout

Create (or align to) this minimal structure:

```text
src/
  events.ts       # placeholder only in this TODO (can be empty export or comment)
  payloads.ts     # placeholder
  types.ts        # placeholder
  helpers.ts      # placeholder
  index.ts        # internal barrel re-exporting public symbols (may re-export nothing useful yet)
  public-api.ts   # single public entry used by package "exports" / "types"
```

Rules for placeholders in this TODO:

- Files may export nothing or a single harmless placeholder (e.g. a `SCHEMA_VERSION = 1` constant) **only if** needed so the build does not fail on empty modules.
- Prefer **empty modules that compile** over fake API surface.
- Do **not** implement real `MFE_EVENTS`, payloads, or helpers here.

### 4. Package entry points

- [ ] Configure `package.json` so consumers can:

  ```ts
  import { ... } from '@cobranza-apps/mfe-events';
  ```

- [ ] Typical fields (adapt to chosen build tool):

  ```json
  {
    "main": "./dist/public-api.js",
    "module": "./dist/public-api.js",
    "types": "./dist/public-api.d.ts",
    "exports": {
      ".": {
        "types": "./dist/public-api.d.ts",
        "import": "./dist/public-api.js",
        "default": "./dist/public-api.js"
      }
    }
  }
  ```

- [ ] Secondary entry points (`./events`, `./payloads`, etc.) are **optional** and should be skipped in this TODO unless trivial with the chosen bundler. Document the decision in a short comment in `package.json` or README if skipped.

### 5. Build script

- [ ] Add scripts, for example:
  - `"build"`: compile to `dist/`
  - `"typecheck"`: `tsc --noEmit`
  - `"clean"`: remove `dist` (optional)
- [ ] Running `npm run build` (or `pnpm build`) must produce `dist/` with `.js` + `.d.ts` for the public entry.
- [ ] `dist/` must be gitignored if not already.

### 6. Repo hygiene

- [ ] Ensure `.gitignore` covers `node_modules/`, `dist/`, coverage, editor files, etc.
- [ ] Do not commit secrets or local env files.
