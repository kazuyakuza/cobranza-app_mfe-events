# Improve @cobranza-apps/mfe-events Consumer Documentation for reflect-metadata

**Scope:** Documentation only — no code changes to the library

## Problem

The `@cobranza-apps/mfe-events` library requires consumers to manually load the `reflect-metadata` polyfill before importing the library. This is because the library uses `class-validator` decorators on internal DTOs, and `class-validator` requires `reflect-metadata` for decorator metadata.

However, `reflect-metadata` is a **CommonJS-only package** (no ESM entry point). In modern Angular projects using:

- **Native Federation** with `es-module-shims` — `import 'reflect-metadata'` fails with `Unable to resolve specifier 'reflect-metadata'`
- **Vitest / Jest in Node** — `import 'reflect-metadata'` works fine

This means consumers need **two different loading strategies** depending on the environment, which is not well documented.

## What Already Works (Verified in Shell angular project)

The Shell angular project (`cobranza-shell`) has already solved this with a dual-strategy approach:

### Browser / Dev Server / Production

Load `reflect-metadata` as a global script via `angular.json`:

```json
{
  "projects": {
    "shell": {
      "architect": {
        "build": {
          "options": {
            "scripts": [
              "node_modules/reflect-metadata/Reflect.js"
            ]
          }
        }
      }
    }
  }
}
```

**Why this works:** The Angular application builder (`@angular/build:application`) loads `scripts` as global JS before the application bootstrap. This is the correct way to load a CommonJS polyfill in an esbuild + ESM environment.

### Vitest Unit Tests

Load via `vitest.config.ts` setupFiles:

```typescript
// vitest.config.ts
export default defineConfig({
  test: {
    environment: 'node',
    setupFiles: ['src/test/reflect-metadata-setup.ts'],
  },
});

// src/test/reflect-metadata-setup.ts
import 'reflect-metadata';
```

**Why this works:** Vitest's Node environment resolves the CommonJS `node_modules/reflect-metadata` package natively.

### What Does NOT Work

❌ `import 'reflect-metadata';` in `src/main.ts` — fails in browser because `es-module-shims` cannot resolve the CommonJS specifier.

```markdown
## Runtime Setup

`@cobranza-apps/mfe-events` uses `class-validator` decorators internally. The library **does not bundle `reflect-metadata`** — you must load it in your application entry.

### Angular Projects (with esbuild / Vite)

Add to `angular.json` (or equivalent builder config):

```json
"scripts": ["node_modules/reflect-metadata/Reflect.js"]
```

Do **not** use `import 'reflect-metadata';` in `src/main.ts` — it will fail in ESM environments.

### Node.js / Test Environments

Import the polyfill in your test setup:

```typescript
// test-setup.ts
import 'reflect-metadata';
```

Or configure your test runner (Vitest, Jest) to load it before specs.

### Why Two Different Ways?

`reflect-metadata` is a CommonJS package. ESM module shims (used by Native Federation, Vite dev server) cannot resolve CommonJS specifiers. The Angular builder's `scripts` array loads it as a traditional global script, which works in all browser environments.
